48. **개(동물)/NNG 미수리의 진짜 병목은 FST 슬롯이 아니라 코드북 임계** (2026-08-05, #43 후속 조사). `개가 짖는다`→개/NNB의 원인을 "FST가 POS 2개만 pack"으로 기록해뒀으나, 실측하니 **`MIN_SUFFIX_FREQ=75`**가 병목이었다 — 코드북에 `개를`[개/NNG+를] freq 144·`개의`[개/NNG+의] 127은 통과해 아크가 있고(그래서 `개를 키우고`·`개를 입양했다`는 이미 NNG로 맞다), `개가`(72)·`개는`(62)·`개와`(50)·`개도`(13)는 탈락해 아크 자체가 없다. **3-POS pack은 기각**: u64 상위 16비트가 남아 있지만(pos3 8bit + qfreq3 8bit로 정밀도 축소 필요) 자동 이득 대상이 NIKL freq≥100 표제어 4,272개 중 **22개뿐**이고 그 22개가 `그·내·군·달·자·사·줄·가지` 같은 단음절 고빈도 동형어 — #37에서 순회귀로 기각된 계열이다. 실효 규모도 작다(v15k 개/NNG 2건, held-out 23건). **대안 실측**: 후처리 룰 [직전이 NR/SN/MM이나 `여·몇·수·여러·반`이 아님] + [직후 조사] → NNG는 NIKL 전수에서 **57건 발동·57건 정답·오폭 0**(커버리지는 개/NNG 126건의 45%). **수리 랜딩**(커밋 a7bf591): `SPOKEN_SUFFIX_BUMPS`에 개가 100·개는 100·개와 80·개도 80으로 등재 → `개가 짖는다`가 개/NNG로 교정되고 수량 표현(`사과 두 개를`·`여러 개가`·`5000여 개의`·`양파 반 개를`)은 전부 NNB 유지, v15k 0.9596·held-out 0.9114 불변, 모델 +416B. **`개는 인간의 친구다`는 미수리** — NIKL이 개는 = NNB 430 : NNG 62로 7배라 freq를 더 올리면 `몇 개는 남았다` 계열이 위험해진다. 후처리 룰은 이 bump로 대체되어 불필요.

    **(a) S1 lazy k-best — 구현 완료 후 기각** (브랜치 `s1-lazy-kbest`에 보존, main 미병합). `viterbi_nbest`의 "상태별 k개 정렬 삽입 DP"를 "1-best 전방 패스 + 우선순위 큐 지연 추출"(Huang & Chiang 2005 Alg.3의 1차원 케이스 = k-way merge)로 교체. 우리 DP 상태가 이미 `(위치, POS쌍)`으로 인코딩된 state-augmented DAG이라 정확 k-best 전제는 충족한다. **착수 근거였던 k 스케일링 실측**(9,000문장, native, 교차 min): k=1 1.117 / k=2 1.276 / k=3 1.424 / k=5 1.600 / **k=10 2.138s** — k당 0.108s 선형, k=1 대비 1.91×(#39의 DP 1.95×와 정합). 기대 1.4~1.6×였으나 **실측 1.20×**(eager 2.144 vs lazy 1.783, 교차 6회 min ×2라운드). **원인: lazy는 k와 무관한 고정 오버헤드 +0.33s**(전방 패스가 모든 진입 간선을 적재)를 먼저 지불하고 k-스케일링에서 0.68s를 되번다 — **k=2에서는 오히려 느리다**(1.634 vs 1.301). 최적화 2회로 1.18→1.20×에서 수렴: KEdge 죽은 필드 제거(`prev_pos`·`prev_state`는 미사용)+용량 예약은 효과 없었고(1.841→1.831), 파생 저장 arena화+힙 예약이 유효했다(→1.769). 프로파일상 남은 할당은 `analyze_topn` 토큰 String·`build_lattice` 사전 materialize로 #35가 이미 "얇게 분산, 단일 레버 없음" 판정한 기존 비용이다. **판정: 1.2×를 위해 상태 그래프+지연 추출기+재현 불가한 동점 의미론을 떠안을 이유가 없다.**

    **(b) 동점 순서는 고정 전순서로 재현 불가 (이론적 발견)**. 트라이그램 비용이 u8 양자화라 f32 동점이 만연하다 — k=10에서 9,000문장 중 **6,269건**이 eager와 갈린다. eager의 동점 규칙은 세 동작이 얽혀 있어 어떤 전순서로도 표현되지 않는다: ①리스트가 차기 전엔 `partition_point(|c| c < cost)`가 신규를 동점들 *앞*에 꽂아 **역순**으로 쌓이고 ②차면 조기 break가 동점 신규를 **거부**하며 ③더 나은 항목이 오면 동점 중 **먼저 처리된 것**이 밀려난다. 같은 후보 집합도 도착 순서에 따라 생존자가 달라진다(반례: K=2에 A(5),B(5),C(3) → [C,B] / A(5),C(3),B(5) → [C,A]). **다만 실제 파급은 작다**: 6,269건 중 토큰열 차이는 **7건**뿐이고 나머지는 전부 아크 분해(span) 차이, 최종 공개 API 기준으로는 25,407문장 중 **4건**. **프로덕션 토큰열(text/pos)은 25,407문장 전부 동일**이라 F1은 정의상 불변이었다.

    **(c) A1(판별 학습 비용 모델) 정찰 — 서브에이전트 No-Go는 계측 오류, 근거 교체 후 여전히 보류.** 1차 측정은 "타일링 가능 0.04% → 명백한 No-Go"였으나 **타일링 DP에 공백 pass-through가 없었다**(Rust 디코더는 공백을 아크가 아닌 별도 단계로 넘어가는데 DP는 아크만으로 0→n 연속 피복을 요구) — 띄어쓰기 있는 문장이 기계적으로 전부 "불가"가 됐고, 전체 유일 통과 사례가 `도와달라.`(공백 없음)인 게 단서였다. **양성 대조를 게이트로 세워** 잡았다: "골드가 top-100에 실재하는 문장"에 같은 판정기를 걸어 통과율을 본다 — 결함판 **0.8%** → 수정판(공백 통과 + 형태소 단위 context-free 정규화) **91.1%**. 수정 후 실측: |F|=1,483(16.5%) 중 **타일링 가능 505건(34.1%)**, 생성 결손 978건(65.9%). 이는 #41의 "그 클래스는 순위 문제가 아니라 경로 조립 문제라 재점수화로 접근 불가"를 **부분 정정**한다. 그럼에도 A1은 보류: 505건 중 26.9%가 표면 분절 동일·POS만 다른 컨벤션이고 최다 항목 `오늘 NNG↔MAG` 33건은 **골드 자체가 오늘=NNG/내일=MAG로 엇갈리는 노이즈**다(그 외 하·되·시키 VV↔XSV, 있 VA↔VV, 전 NNG↔MM 전부 기존 천장 판정 계열). **부산물: 생성 결손 978문장이 트랙③의 구체적 작업 목록.**

    **(d) 다어절 NNP span 잘림 수리** (커밋 `88833a1`, main 반영). span 재할당이 토큰이 한 어절 안에 있다고 가정해 `token.start`가 속한 첫 어절 범위를 통째로 씌웠다 → 공백 포함 고유명사가 표면보다 짧게 잘렸다(`여수 밤바다/NNP[0:2]`, `류마티스 관절염/NNP[0:4]`). 겹치는 어절을 모두 합치는 `eojeol_span_for()`로 통일. 단일 어절 토큰은 동작 동일이라 **토큰 출력 불변, span 변화 18문장뿐**. tradeoff: 다어절 아크의 앞쪽 토큰(`거의/MAG` 등)은 어절 합집합을 받아 정밀도가 낮아진다 — 어절 단위 span 컨벤션과는 일관.

    **함께 랜딩**: 출력 불변 검증 하니스 `training/verify_byte_identical.sh`(v15k 9,000 + 구어 16,407 byte 비교, 커밋 `3b059d0`), 어절 캐시 아크 주입 일원화(`inject_cache_arcs`, 커밋 `301e30a` — `analyze`/`analyze_topn` 중복 제거). **측정 교훈 2가지**: ①서브에이전트 측정이 극단값을 내면 **양성 대조 없이 받지 말 것** ②`analyze_batch`는 `text\tpos`만 찍고 span을 안 찍으므로 "byte-identical 통과"가 span 불변을 뜻하지 않는다.

    관측된 캐시 표면2,076종 중416종에는 서로 다른 참조 분석이 있었다. 예: `SARW2400000003.1.1.2`의 `단`은 캐시·출력 MM, 참조 MAG다. 반면 `.1.1.8`의 `궁금해하실`은 `궁금하+아+하` 대 `궁금해하`의 분절 차이다. `되/VV↔VX`, 문장부호 누락도 섞여 있으므로 참조 차이를 전부 언어 오류로 취급하지 않는다. **후속 가설은 문맥 조건부 대안 캐시**이며, 이 진단만으로 채택하지 않는다. 기존 학습 자료에서 대안을 만들고 별도 개발 문서로 선택한 뒤 실제 native 경로·고정 평가·도메인·파일 크기·WASM 비용을 비교해야 한다. 이번에 열람한 구어 정답에서 항목이나 조건을 만들면 평가 오염이다. 모델 학습·캐시 변경·새 조건의 구현은 수행하지 않았다.

    **실행 경계와 보존.** Node24.13.0/arm64의 기존 WASM으로 골드9,000문장5회 측정한 누적 시간 중앙은2.8625s(평균0.3181ms/문장), 회차별 p95 중앙0.6633ms였다. 모델 로딩은 제외하고 JS API 호출·결과 변환은 포함하며 브라우저 실측은 아니다. native와 같은 `trim()` 입력에서 골드·구어25,407문장의 형태/POS열이 모두 일치했다(span·score 비교는 아님). 원문 입력에서는 구어6761행 `SDRW2400001766.1.1.122`의 후행 공백에 따라 `등등+등` 순서가 달라지는1건이 있었다. 이 문장의 multiset F1은 동일하며, 공백이 탐색 순서에 영향을 주는 내부 원인까지 규명한 것은 아니다. 모델1,247,331B(SHA256 `190e1d2bd63e984377468664f059d8d13acd56aba9df6e8899d0963c724c9b96`), 원본 골드(SHA256 `3a5fa4194b2ae3eec58296674408e8f1d409a72205777044455b9c1b838bbb96`), WASM411,541B를 보존했다. 임시 후보 덤프·입력·캐시 추출본은 진단 후 제거한다.

    **자료와 선정.** 문서 ID 해시로 train/dev/holdout을 나누고, 원본 골드·구어의 NFC·공백 제거 문장 중복, 분할 사이 같은 원문, 기존 재순위 train/dev와 holdout의 정확 일치를 제외했다. 이전 대화에서 읽은8문서도 holdout에서 제외했다. 의역·문단 내부의 과거 학습 문장 중복까지 배제했다는 뜻은 아니다. 한 단어·문서당 한 문단에서 train/dev 각 최대6개, holdout 최대10개를 고정 순서로 뽑았다. 최초 발췌가 `J. Derrida` 등의 약어에서 잘리는 것을 발견해 원본 SHA와 대조한 전체 문단(최대1,000자)으로 복원하고 다시 평가했다. 품사는 용례를 검토해 정한 표적 주석이며 원문 전체를 골드로 승격하지 않았다. 용어 확인의 보조 근거는 식품안전나라의 [테아닌](https://www.foodsafetykorea.go.kr/upload/residue/2-4-485.pdf), 대한화장품협회의 [레티날 구명칭](https://kcia.or.kr/cid/search/ingd_view.php?no=9582), 국립국어원의 [찻종](https://korean.go.kr/front/mcfaq/mcfaqView.do?mcfaq_seq=6274&mn_id=217&pageIndex=24) 등이다. 이 자료가 모든 문맥의 세종 POS를 직접 부여한 것은 아니다.

    **적용.** 기존 freq200 보강 방식을 사용해 일반명사81개·고유명사7개를 `tech_supplement.txt`에 추가했다. 토크나이저·인페인팅, 테아닌·레티날·레스베라트롤·판테놀, 휘낭시에·뇨키·과카몰리, 말라르메·맥루헌 등이 포함된다. 기준 모델의 무변경 정규 빌드가 byte-identical임을 먼저 확인했다. 최종 GMDL은 Section6 사전만 바뀌었고 코드북·트라이그램·어절 캐시·재순위 가중치는 같다. 분석기 코드나 WASM을 변경하지 않았다.

    **보류 근거.** 치아바타는 `오랜 시간`의 시간/NNG→NNB, 구아검은 괄호 뒤 나/JX→NP, 도스토예프스키는 인접 투르게네프의 경계 파괴, 카다이프는 `카다이프면이다`의 이/VCP→JKS 때문에 보류했다. 처음 네 개를 뺀90개 모델의 holdout 검토에서 프리바이오틱스는 띄어 쓴 와/JC→오/VV+아/EC, 바쿠치올은 인접 `레티놀의`의 의/JKG를 통째 명사에 삼키는 문제가 추가로 확인됐다. 각각 제외 후 올바르던 부분의 복구를 확인했다. 어절 전체 span이 목표 어휘와 겹친다는 이유로 같은 어절의 나머지 토큰 변화를 숨기면 계사 회귀를 놓친다. 표면이 같은 토큰의 POS 변화도 별도로 검사하고, 대표 양성11항목과 문맥 회귀5사례를 테스트로 남겼다.

    **최종 평가.** 원본 골드9,000문장은 형태·POS·위치가 동일하며 norm F1 **96.040446%**, raw F1 **93.443870%**를 유지했다. 구어16,407문장은 뇨키4문장의 NNP→NNG만 개선되어 norm F1 **91.184587→91.186495%(+0.001908pp)**이며 문장 F1 악화는0건이다. 도메인별 골드 점수도 같다. 새 원문 표적의 단어·품사 인식은 train479등장 **71→479**, dev383등장 **56→381**, 별도380문서452용례의500등장 **77→498**이다. 이 마지막 자료를 보고 두 항목을 제외했으므로 최종값은 **선택 후 검증**이며 완전 미열람 일반화 점수가 아니다. 전체 문단 F1도 아니다. `먹태브리오슈` 내부의 브리오슈와 짧은 인용 표기 `-자크 데리다`는 여전히 놓친다. 해당 사례 전용 규칙은 추가하지 않았다.

    **비용과 검증 경계.** Brotli 완성 모델은 **1,247,331→1,248,507B(+1,176B)**, gzip 전송 크기는1,247,589→1,248,729B다. 같은1,250입력(골드 간격 표집1,000+원문250)·준비 실행50·7회 교차 측정에서 native 시간 비율 중앙0.9949, Node WASM0.9829였다. 각 모델의 최저 누적 시간끼리의 비율은 각각0.9991·1.0013으로 뚜렷한 저하를 관측하지 않았으며 가속으로 주장하지 않는다. 모델 로딩·JSON 전송은 native 시간에서 제외하고 WASM은 JS API 결과 변환을 포함한다. 실제 브라우저 측정은 아니다.

71. **공백 없는 한국어의 공백 복원·문장 경계 추정 — 별도 JS 선택 기능 채택** (2026-10-20). 사용자가 요청한 범위는 붙여 쓴 단어의 공백 복원과 붙어 있는 여러 문장의 분리 둘 다였다. 기존 `splitSentences`는 구두점·공백 정규식이고 분석기 내부에서 자동 호출되지 않는다. 무공백 입력에서는 어절 캐시 exact lookup과 출력 span의 공백 기준 확장이 제약이므로 기존 토큰 span을 공백 위치로 그대로 쓰지 않았다. 기본 `analyze`와 기존 `splitSentences` 동작은 유지하고 `garu-ko/text`에 동기 `restoreSpacing`·`splitUnspaced`를 추가했다.

    **모델과 선택.** NIKL2021의 공백·문장 정보를 문자 경계로 변환하고 문서 분할·고정 자료·공백/종결부호 삭제 변형 중복을 차단했다. 공백 head는245,815개 원본 문장, 문장 head는100,000개 원본문장 풀에서 완결 조건을 만족하는 부분으로 학습했다. 공통2^19·13특징 형식 안에서 각 head를 개발 지표로 선택했다. 13종 국소 문자 n-gram·문자종류·bias의 해시 선형 모델이며 각 head 2^19개 int8 가중치다. 왼쪽4자·5gram 확장은 이 비교에서 이득이 없어 폐기했다. 공백의 balanced는 경계 dev F1로, 기본 conservative는 학습에서 제외한 기존 dev6,000문장의 복원 후 형태소 F1로 임계값을 골랐다. 선택 뒤 고정셋 검증이며 반복 열람한 test를 완전 미열람 성능으로 부르지 않는다.

    **형태소 분석 효과.** 같은 고정 문장에서 공백만 제거한 입력과 기본 보수 복원 후 최종 WASM 분석을 비교했다. 골드 F1은 **0.9259646612→0.9330748786**, 구어는 **0.8521064328→0.8800514875**다. 정상 공백의 최종 분석 점수0.9605382326·0.9122738396까지 회복한 것은 아니다. 기술·문학·SNS 등 일부 골드 도메인은 복원 후 악화가 남았으므로 자동 전처리로 적용하지 않았다. `아버지가방에들어가신다`처럼 모호한 문장은 기본 모드에서도 `아버지가방에 들어가신다`로 남고, balanced는 잘못된 공백을 더 넣을 수 있다.

    **학습과 정책의 효과 분리.** 기존2025NX9,355문단에서 공백 삭제/공백·종결부호 삭제 F1은 기존82.7147/83.5242%, 학습 검증만85.5558/86.0617%, 인용문 보호만94.1678/95.0149%, 둘을 결합한 실제 JS API는 **95.7347/96.3006%**다. 무종결부호의 TP/FP/FN은 기존4157/1490/150→최종4139/150/168이다. 학습의 추가 효과는 같은 인용문 보호 대조군 대비1.2857%p이며, 전체 상승을 신경 모델의 효과로 부르지 않는다. 같은 보호 정책에서 문자 문맥 제외95.2952%, 형태소 제외96.2119%, 쉬운 음성 학습95.3981%였다. 효과는 서로 더할 수 있는 독립 기여도가 아니다. 두 번째 seed의 결합 결과는95.4976/96.1208%였다.

    **참조 기준 충돌.** 2021 원본 source-record는 항상 바깥 문장 기준이 아니다. 정상 ASCII/curly 큰따옴표 한 쌍만 있는 train7,233행에서도 인용 내부 원본 정답2,013개가 있었으나, 같은 조건의2025 자연1,019문단에는0개였다. 예를 들어 `NWRW1800000049.312.9.1/.2`와 `NWRW1800000048.331.10.3/.4`는 보도절로 이어지는 인용 내부도 나눈다. 새 보호 규칙 때문에 원본2021NX test의 무종결부호 F1은 학습 검증만94.6410%에서92.4289%로 내려간다. 원본 정답을 바꾸지 않고 이 하락을 함께 기록했다. 2025 오류를 본 뒤 추가한 정책이므로 고정셋의 사후 개선이며, 일반 뉴스·대화에서95%를 보장하거나 미열람 최종 평가라고 부르지 않는다. 기존의 ‘source-record=top-level’ 표현은 이 관찰에 따라 정정했다.

    별도 판독 구어48개·양성8경계에서는 부호 유지 TP5/FP4/FN3→5/2/3, 부호 삭제2/4/6→2/2/6이었다. 작은 선택 표본이며 독립 전문가 골드나 구어 전체95%의 근거가 아니다. 검증기는 기존 후보를 거부할 뿐 누락 경계를 새로 만들지 못한다. 짝이 없는 인용부호와 모호한 직선 따옴표의 의도는 완전히 해석하지 않는다. 중첩·혼합 인용부호, Latin 단어 내부·소유격 apostrophe의 실제 회귀 사례를 검사했다.

    **모델·비용·런타임.**198,937파라미터의 문맥 임베딩과ReLU dense 모델이다. 어휘·스케일·bias·임계값을 포함한 완성 Q4 JSON174,894B, 배포 JS 데이터178,676B(gzip117,403B), 선언 파일196B다. Q4는 전달 형식이며 추론 때 float32 배열로 복원하고 JS에서 계산한다. Node24/V8에서1250문단(두 조건625개씩), 준비50·7회 교차 측정의 합계 중앙값은 기존54.713ms, 인용문 보호만56.647ms, 결합1373.105ms였다. 문단당 약1.10ms, 기존 대비쌍별 중앙25.106배로 느리므로 선택 기능으로 둔다. 모델 로딩을 제외한 Node 결과이며 브라우저 대규모 지연 수치가 아니다. 실제 Chrome155에서는 네트워크를 끈 뒤7개 사례와100회 반복이 성공했고 추론 요청0개·페이지 오류0개였다.

    **검증·보존.** PyTorch2.8.0 MPS가 padding_idx의 gradient를 막지 않는 현상을 CPU 대조로 재현했다. 명시적 padding 마스크와 export 영 벡터 검사를 추가한 뒤 모든 모델을 다시 선택했고 초기 잘못된 모델은 폐기했다. 독립 검토에서4모델·71,160개 실제 JS/NumPy 점수의 최종 경계 불일치0, 최대 score 오차5.183e-6이었다. 비유한/다차원 점수, source/feature SHA와 음성 표본 길이도 검증한다. JS55개·관련 Python29개·타입 검사·독립 패키지 import를 통과했다. 코드·선택 모델은 저장소에, 원문 없는 ID/변형/후보 정답 참조는 `~/workspace/data/korean_sentence_verifier/20261020/`에 보존한다. 전체 근거는 `training/boundaries/review_verifier_20261020.json`, 배포 모델 계보는 `js/models/sentence-provenance.json`이다. 폐기 모델·중복 입력·예측 덤프·작업 복사본은 적용 확인 뒤 정리했다.

74. **경량 문장 검증기의 속도·정확도 비교 — 평균20µs/문단** (2026-10-20). 문자 문맥 검증과 FNV 계산 전개를 결합한 문장 분리는 로드 후 문단당 평균 **Node20.04µs·Chrome17.92µs**로 측정됐다. 고정 뉴스 평가셋의 경계 F1은 공백 삭제95.91%, 공백·종결부호 삭제96.28%였다. 같은 입력에서 형태소 검증 방식의 평균은1,072.67µs로, 경량 방식은 약53.5배 빨랐다.

    **실험 구성.** 비교 대상은 형태소 정보를 사용하는 `splitSentences(text, garu)`와 문자 문맥만 사용하는 `splitSentences(text)`다. 기존 정밀 경로는 형태소 분석이 시간의 대부분을 차지했고, 기존 신경망 계산만으로도 문단당45µs를 넘었다. 경량 방식은 형태소 분석을 생략하고 작은 검증기를 사용한다. 첫 단계 문자 경계 모델의 가중치·임계값은 동일하며, exporter에서 FNV 점수식을 펼쳐 반복 계산 비용을 줄인다. 동적 코드 생성이나 결과 캐시는 사용하지 않았다.

    **학습·선택.** #73과 같은134,055학습행·123,042양성·7,318오분리 후보를 사용했다. 형태소9개 특징을0으로 두고 C12/E8/H32와 C24/E8/H32를 비교해 개발 macro F1 88.6139→88.8178%인 후자를 선택했다. seed20261020, epoch9, threshold0.2, 41,737파라미터이며 교사 모델 출력으로 증류하지 않았다. 완성 Q4 JSON은69,458B, JS 모듈 gzip46,261B다. 원본부터 재생성한 train/dev/test SHA는 #73과 일치했다. 공식 학습 경로 재실행도 같은 epoch·임계값·개발/테스트 계수를 선택했다. MPS의 작은 scale/bias 차이로 파일 해시는 달라졌지만 Q4 코드와 평가 결정은 같았고, 재현 경로의 산출물을 정본으로 채택했다.

    **정확도·실패 범위.** 실제 기본 JS API의2025NX9,355문단 F1은 공백 삭제95.9126%(TP4083/FP124/FN224), 공백·종결부호 삭제96.2842%(4120/131/187)다. 이전 정밀95.7347/96.3006%와 비교하면 +0.1779/−0.0164%p다. 인용문 정책은 그대로이며 고정셋을 이미 본 후속 검증이다. 원본2021NX test는 인용문 보존 후93.0953/92.3176%, 약한 구어 라벨은89.6552/71.3364%다. 별도 검토 구어48행·정답8경계는 이전과 동일한5/2/3 및2/2/6으로 남았다. 일반 구어95% 달성으로 해석하지 않는다.

    **측정 조건.** Apple M4, Node24.13.0, 평균82.5368코드포인트인1,250입력에 warmup50회 후7회 경로를 순환해 측정했다. 위 속도는 각 회차 평균의 중앙값이며, 기존 인용문 보호만의 비교 경로는45.56µs였다. 경량 방식의 Node 입력별 P50/P95는8.42/60.96µs로, 평균값과 개별 문단의 지연 분포는 구분해야 한다. import44.25ms·첫 호출5.86ms는 별도이며 OS 파일 캐시는 통제하지 않았다. 두 모델을 정적으로 가져오므로 빠른 경로도 전체 모듈을 파싱한다. 실제 Chrome155에서도 같은 표본을 측정했다. 네트워크 차단·동적 코드 생성 불허 CSP에서1,250입력의 Node/Chrome 출력 불일치0, 추가 요청0이었다.

    **대조·검증·정리.** 개발셋만으로 선택한 임계값−0.65와 기존 인용문 보호만의 조합은 고정셋94.5930/95.3093%여서 두 조건95% 목표를 충족하지 못했고 채택하지 않았다. 최종 경계 가중치·기존 full 검증기·GMDL·WASM은 유지했다. 독립 검토는 FNV39,344점수, 무작위 Unicode400입력의 후보·복원·형태소 특징, 기존 정밀264문단 출력의 일치를 확인했다. JS57개·Python30개·타입 검사·분리한 npm 패키지의 두 호출을 검증했다. 현재 npm pack은1,999,781B로 이전 스냅샷보다49,892B 증가했다. 근거·계보는 `training/boundaries/review_speed_20261020.json`과 `js/models/sentence-provenance.json`, 재현 명령은 `training/boundaries/README.md`에 둔다. 폐기된 작은 후보·중복 문단·특징 캐시·측정 복사본은 정리하고 원본 말뭉치·기존 참조와 채택 코드·모델을 보존한다.

75. **비캐시 어절까지 문맥 POS 교정 확장 — 전체 F1 상승, 문학 회귀로 미채택** (2026-10-26). 사용자 요청으로 #70의 정확한 캐시 일치 제한을 넘어서는 교정을 실험했다. 보존된 문서 참조에서 학습285,152문장·6,907문서와 개발27,748문장·781문서를 원본 NIKL2021로 복원했으며 준비 파일 해시가 기존 기록과 같았다. 문서·공백 제거 텍스트의 분할 간 중복은 없고, 고정 골드·2025구어·기존 dev는 텍스트 중복 차단에만 사용했다. 기본 분석기의 기존 NIKL 노출과 반복 고정 평가 이력은 남는다.

    **학습과 적용 위치.** 현재 `Analyzer::analyze`의 최종 형태·POS·span을 실제로 생성하고, 형태소열은 같으면서 POS 하나만 다른 정답을 채굴했다. 이미 정답인 문맥을 포함한 다른 참조를 음성 사례로 집계했다. 32개 개발 설정 중 문맥 정밀도98%·최소8건·3문서 조건의260규칙·660가드를 선택했다. 원래 캐시열과 일치하는 규칙53개, Section13에 표면이 없는 어절 대상176개, 표면은 있으나 최종 분석열이 다른 대상31개다. native 연구 helper에서 기존 Section16 이후 정확한 원래 형태/POS/span이 맞을 때 한 POS만 바꾸며 사용자 단어를 보호했다. 형태·토큰 수·순서·span·점수는 유지한다. 후보 아크나 분절을 추가하지 않았다.

    **동결 후 고정 평가.** 골드9,000문장 ep_norm F1은 **96.053823→96.091643%(+0.037820pp)**, 구어16,407문장은 **91.227384→91.295119%(+0.067735pp)**다. 문장별 골드는47개선·11악화·1동률, 구어는151개선·14악화·12동률이다. 골드 문학은 **−0.017840pp**로, 0-based3957행의 `있/VV→VA`가 참조 TP 하나를 잃었다. 기술·엣지는 같고 다른 골드 도메인은 올랐다. 캐시에 표면이 없는176규칙만 적용한 분해에서도 골드+0.024881pp·구어+0.055810pp였으나 문학 회귀는 남았다. 평가를 본 뒤 항목을 빼거나 임계값을 다시 고르지 않았다.

## 영문 원문 아카이브 — CNN 재순위 시절 (폐기: +700KB 대비 +0.2%p)

2026-09-04 AGENTS.md 정리 때 옮김. 아래 두 절은 CNN 을 현행으로 전제하던 시점의 영문 기술이라 **현재 구조와 다르다**(현행은 재순위 perceptron, `cnn.rs` 삭제). 기록용으로만 둔다.

### Current Architecture (영문 원문, CNN 시절)

Pipeline:

```text
input text
  -> sentence-level lattice construction
     - FST content-word dictionary
     - suffix codebook
     - smart eojeol cache as low-cost arcs
     - typo-tolerant OOV arcs
  -> trigram N-best Viterbi decoding
  -> postprocessing rules
     - VCP split
     - VX/JC/JKC/NNB/XSN/XPN/MM/XSV/XSA corrections
  -> CNN reranking / agreement scoring
  -> token output
```

### Important model pieces (영문 원문, CNN 시절 — `cnn2.bin`·`cnn.rs` 는 삭제됨)

Important model pieces:

- `codebook.gmdl` / `js/models/base.gmdl`: GMDL binary model with FST dictionary, suffix codebook, sparse trigram costs, word-bigram adjustments, parameters, and smart eojeol cache.
- `cnn2.bin`: small int8 1D CNN used for reranking and POS correction.
- `crates/garu-core/src/model.rs`: analyzer orchestration.
- `crates/garu-core/src/codebook.rs`: lattice construction, Viterbi, cache injection, and postprocessing.
- `crates/garu-core/src/cnn.rs`: quantized CNN inference.
- `crates/garu-core/src/trie.rs`: FST dictionary and multi-POS packing.
- `crates/garu-core/src/types.rs`: Sejong POS tags.
- `crates/garu-wasm/src/lib.rs`: WASM bindings.
- `js/src/index.ts`: public JS/TS API.
